# Gateway 模式设计规格

**状态：设计阶段，代码尚未实现。**
本文件描述"协议接入网关"这一运行形态的目标语义，用于约束后续实现。
早期分支上曾出现过把该形态做成 `server.mode` 开关的实验性代码，已回退；
本规格与现有代码的开关无关，实现时按本文件重新落地。

判断依据来自对以下代码的逐条核对：

- `internal/protocol/msg_processor.go`（消息注册表与处理函数）
- `internal/storage/`（全部内存缓存与响应协调器）
- `internal/action/`（生命周期钩子与 HTTP 回调示例）
- `internal/server/`、`internal/protocol/pipeline.go`（会话与传输可靠性）
- `internal/api/`（单机 HTTP API 对缓存的依赖）

---

## 1. 定义边界

**一句话：** gateway 模式负责"协议接入 + 连接现场状态 + 旁路通知"，
不承担业务数据存储与业务查询服务。

| 负责 | 不负责 |
|---|---|
| TCP/UDP 接入、拆帧/转义/校验、消息头解析 | 业务数据的持久化或缓存（定位历史、报警、行业载荷） |
| 分包重组、协议应答、下行分包的补传缓存 | 北向 HTTP/业务 API（设备列表、历史轨迹、报警查询等） |
| 终端注册/鉴权/心跳/注销带来的连接现场状态 | 终端模拟器行为（参数/属性/区域目录、媒体回放等） |
| 把终端上行的业务事实通过 `internal/action` 钩子旁路外发 | 平台下行命令的编排与调度（由北向系统负责，本规格不定义） |
| 会话级在途消息确认、设备在线/休眠/保活判定 | 业务数据的去重、聚合、幂等落库（由下游负责） |

两点推论：

1. **"不落 storage"指业务数据不落。** 连接现场（`DeviceCache`、`SessionCache`）
   与传输可靠性（`SegmentCache`、`sentSegmentCache`）是 gateway 自身运行必需的，
   必须保留，否则鉴权、重复注册判定、保活、分包重组都无法完成。
2. **gateway 的入站只有终端上行消息（`MsgID < 0x8000`）。**
   平台下行消息（`MsgID >= 0x8000`）不属于接入网关的终端入站范围；
   若未来需要从 gateway 下发命令，应由北向系统发起，属于 M3/M4 的接口设计。

## 2. 消息处理矩阵

### 2.1 策略口径

| 策略 | 含义 |
|---|---|
| 自行处理 | gateway 维护连接现场或传输可靠性状态，无业务外发 |
| 自行处理 + Hook | 在自行处理之外，把业务事实通过 `internal/action` 外发 |
| 仅协议应答 | 只完成协议层解析与应答，无业务副作用 |
| 忽略 | gateway 不注册或不处理该消息 |

表中的"写内部存储"只统计业务缓存；传输层缓存（session/device/segment）单独标注。

## 3. 存储归属矩阵

`internal/storage` 下共有 14 个缓存/协调器。判定原则：
**连接现场与传输可靠性保留，业务数据与模拟器目录外发或忽略。**

| 缓存 | 数据结构 | gateway 保留 | 依赖它的流程与补偿方式 | 理由 |
|---|---|---|---|---|
| `DeviceCache`（`device_cache.go`） | `map[plate]`/`map[phone] -> model.Device`（ID、车牌、手机号、SessionID、传输类型、Conn、Keepalive、LastestComTime、Status、版本、AuthCode、IMEI、软件版本） | **保留** | 0x0100 重复注册与鉴权码生成、0x0102 鉴权、0x0002 心跳、0x0003 注销、0x0200 合法性校验与 ACC 休眠、保活定时器 | 连接现场与身份校验的最小依据；丢失会导致鉴权/在线判定失效 |
| `SessionCache`（`session_cache.go`） | `map[sessionID] -> *model.Session` | **保留** | accept/清除、0x0001 应答确认、北向发送、连接数监控 | 纯连接现场，不含业务数据 |
| `SegmentCache`（`segment_cache.go`） | `map[phone/msgID/firstSerial] -> segmentState`，TTL 2 分钟，单消息最多 4096 分片 / 16 MiB，最多 1024 条 | **保留** | 大消息（0x0104/0x0200/0x0801 等）的分包重组；与 `packet_codec.go` 直接耦合 | 传输可靠性，与业务归属无关 |
| `sentSegmentCache`（`sent_segment_cache.go`） | `entries map[phone/serial] -> frames` + `media map`，TTL 2 分钟 / 16 MiB | **保留** | 下行分包缓存，支撑终端 0x0005 与平台 0x8003 的补传 | 传输可靠性；gateway 下发分包时必须保留 |
| `GeoCache`（`geo_cache.go`） | `map[phone] -> ring buffer`，容量 100，元素为 `DeviceGeo` | 不保留 | 原依赖：0x8201 位置查询、HTTP API 轨迹、保活清理。补偿：`OnLocation` 已外发；北向查询见 C3；不创建则无需清理 | 业务数据（定位历史） |
| `AlarmCache`（`alarm_cache.go`） | `events map[phone][]*AlarmEvent`（每设备 1000 条，30 分钟内同流水号合并）+ `commands map`（0x8203 确认关联，10 分钟过期） | 不保留 | 原依赖：0x0200 记录、0x0001 对 0x8203 确认、HTTP API 报警查询。补偿：`OnAlarm` 外发；平台 0x8203 关联见 C1 | 业务数据（报警事件） |
| `IndustryCache`（`industry_cache.go`） | 20+ 个按手机号的业务映射（0x0700/0x0701/0x0702/0x0704/0x0705、0x0800/0x0801/0x0802/0x0805/0x1205、0x0301/0x0302/0x0303、0x0900/0x0901、0x0500、升级、电话本、事件/菜单目录等） | 不保留 | 原依赖：`processIndustryReport`、模拟器 0x9205/0x8802/0x8803、HTTP API。补偿：业务事实由下游接收；当前钩子只覆盖位置/报警（C4/C6） | 业务数据 + 模拟器目录 |
| `RegionCatalog`（`region_catalog.go`） | 每设备的圆形/矩形/多边形/路线四类 `map[id]` | 不保留 | 原依赖：0x8600/0x8602/0x8604/0x8606 设置、0x8601/0x8603/0x8605/0x8607 删除、0x8608 查询、HTTP API | 模拟器目录；gateway 不下发区域命令 |
| `DeviceParamsCache`（`param_cache.go`） | `map[phone] -> *DeviceParams` | 不保留 | 原依赖：0x0104 应答缓存、0x8103/0x8104/0x8106 模拟器、HTTP API | 业务/参数数据；gateway 无北向参数查询 |
| `LocationTrackingCache`（`location_tracking.go`） | `map[phone] -> {interval, expiresAt}` + 变更通知 channel | 不保留 | 原依赖：0x8202 临时位置跟踪、HTTP API | 平台下行业务控制；gateway 不下发 0x8202 |
| `ParamResponseBroker`（`param_response.go`） | `map[phone/serial] -> chan *Msg0104` | 不保留 | 原依赖：北向发起 0x8104 后等待 0x0104 | 纯进程内等待者关联；gateway 无北向查询，无 waiter（C3） |
| `PropertyResponseBroker`（`property_response.go`） | `map[phone] -> chan *Msg0107` | 不保留 | 原依赖：北向发起 0x8107 后等待 0x0107 | 同上 |
| `LocationResponseBroker`（`location_response.go`） | `map[phone/serial] -> chan *Msg0201` | 不保留 | 原依赖：北向发起 0x8201 后等待 0x0201 | 同上 |
| `RegionResponseBroker`（`region_response.go`） | `map[phone/queryType] -> chan *Msg0608` | 不保留 | 原依赖：北向发起 0x8608 后等待 0x0608 | 同上 |

| 组件 | 位置 | gateway 保留 | 说明 |
|---|---|---|---|
| `KeepaliveTimer` | `internal/protocol/keepalive.go` | **保留** | 依赖 `DeviceCache`，负责超时离线与长期清理；属于连接现场 |

### 3.1 结论：必须自己保存的最小子集

共 **4 个缓存 + 1 个定时器**：

1. `SessionCache` —— 会话句柄与协议确认上下文；
2. `DeviceCache` —— 注册/鉴权/在线/休眠/最近通信时间；
3. `SegmentCache` —— 上行分包重组；
4. `sentSegmentCache` —— 下行分包补传；
5. `KeepaliveTimer` —— 基于 `DeviceCache` 的离线判定与清理。

除此之外，gateway 不保存任何业务数据。若后续需要"业务查询经 gateway 回到终端"，
应通过北向接口 + 钩子扩展（M3/M4）重新引入协程关联，而不是恢复业务缓存。

## 4. Hook 事件契约

当前 `internal/action/hooks.go` 已定义接口；本节把字段含义、单位与可空性明确为契约。
钩子方法均不返回错误：实现方只做旁路通知，任何失败都不得影响协议主流程。

### 4.1 接口

```go
type Hooks interface {
    OnRegister(ctx context.Context, event RegisterEvent)
    OnAuth(ctx context.Context, event AuthEvent)
    OnLocation(ctx context.Context, event LocationEvent)
    OnAlarm(ctx context.Context, event AlarmEvent)
    OnDisconnect(ctx context.Context, event DisconnectEvent)
}
```

默认实现 `action.Noop` 全部为空操作。

### 4.2 字段定义

#### RegisterEvent（来源 0x0100）

| 字段 | 类型 | 单位/取值 | 可空 | 说明 |
|---|---|---|---|---|
| phone | string | 数字字符串（BCD 解码） | 否 | 终端手机号，来自消息头 |
| deviceId | string | 大写字母/数字 | 否 | 终端 ID（2011/2013 为 7 位，2019 为 30 位） |
| plate | string | GBK 解码后的车牌号 | 否 | 车牌号 |
| protocolVersion | uint8 | 0 表示 2011/2013；2019 为递增修订号 | 否 | 消息头协议版本号 |
| versionDesc | string | `"2011"` / `"2013"` / `"2019"` | 否 | 消息头版本判别结果 |
| result | uint8 | 0 成功；1 车辆已注册；2 终端已注册；其他为标准结果码 | 否 | 0x8100 应答结果；钩子在应答生成后触发 |

#### AuthEvent（来源 0x0102）

| 字段 | 类型 | 单位/取值 | 可空 | 说明 |
|---|---|---|---|---|
| phone | string | 数字字符串 | 否 | 终端手机号 |
| imei | string | 字符串 | 否（可能为空串） | 终端 IMEI |
| softwareVersion | string | 字符串 | 否（可能为空串） | 终端软件版本 |
| success | bool | true/false | 否 | 鉴权是否通过（对应 0x8001 结果码 0） |

#### LocationEvent（来源 0x0200 单条、0x0704 逐条）

| 字段 | 类型 | 单位/取值 | 可空 | 说明 |
|---|---|---|---|---|
| phone | string | 数字字符串 | 否 | 终端手机号 |
| serial | uint16 | 消息流水号 | 否 | 0x0200 或 0x0704 所在消息的流水号 |
| alarmSign | uint32 | 位标志 | 否 | 报警标志位，0 表示无报警 |
| statusSign | uint32 | 位标志 | 否 | 状态标志位 |
| latitude | uint32 | 1e-6 度 | 否 | 纬度（协议原始值） |
| longitude | uint32 | 1e-6 度 | 否 | 经度（协议原始值） |
| altitude | uint16 | 米 | 否 | 海拔高度 |
| speed | uint16 | 0.1 km/h | 否 | 速度（协议原始值） |
| direction | uint16 | 0–359 度 | 否 | 方向，正北为 0 |
| time | string | `YYMMDDHHMMSS`（GMT+8） | 否 | BCD 时间字符串 |

说明：0x0704 的逐条事件沿用内层 0x0200 的 `serial`，即外层消息流水号，
不是每条位置独立流水号（协议未提供）。

#### AlarmEvent（来源 0x0200 / 0x0704 中 `alarmSign != 0`）

| 字段 | 类型 | 单位/取值 | 可空 | 说明 |
|---|---|---|---|---|
| phone | string | 数字字符串 | 否 | 终端手机号 |
| serial | uint16 | 消息流水号 | 否 | 同 LocationEvent |
| alarmSign | uint32 | 位标志 | 否 | 非零报警标志位 |
| latitude | uint32 | 1e-6 度 | 否 | 纬度 |
| longitude | uint32 | 1e-6 度 | 否 | 经度 |
| time | string | `YYMMDDHHMMSS` | 否 | 定位时间 |

#### DisconnectEvent（来源会话关闭）

| 字段 | 类型 | 单位/取值 | 可空 | 说明 |
|---|---|---|---|---|
| sessionId | string | TCP 为远端地址，UDP 为远端端点 | 否 | 会话标识 |
| transport | string | `"TCP"` / `"UDP"` | 否 | 传输类型 |

### 4.3 HTTP 回调协议

示例实现位于 `internal/action/http.go`，仅供下游参考；生产实现可用任意方式消费钩子。

| 项 | 约定 |
|---|---|
| 方法 | `POST` |
| Content-Type | `application/json` |
| 地址 | 配置项 `server.action.http.url`；为空时不启用 |
| 超时 | 配置项 `server.action.http.timeoutMs`，默认 2000 ms（按单次请求计） |
| 外层结构 | `{"event":"register|auth|location|alarm|disconnect","occurredAt":"RFC3339","payload":{…}}` |
| payload | 对应 4.2 的事件结构，字段名使用 JSON tag |
| 队列 | 有界队列，容量 256；单 worker 顺序发送 |
| 队列满 | 丢弃新事件并记录 Warn，不阻塞协议流程 |
| HTTP 失败 | 网络错误或响应码 >= 400 只记录日志；**不重试** |
| 投递语义 | at-most-once（可能丢失，不会重复由回调层产生） |
| 顺序 | 单 worker 内先进先出；多协程入队时跨事件不保证全局有序 |
| 幂等 | 协议层不提供事件 ID；下游需自行用 `(phone, serial, event, occurredAt)` 去重 |
| 阻塞性 | 所有钩子调用都不阻塞协议处理主流程 |

## 5. 结论与争议点

### 5.1 结论

1. gateway = 协议接入 + 连接现场 + 旁路通知，不含业务存储与业务查询。
2. 必须自留：`SessionCache`、`DeviceCache`、`SegmentCache`、`sentSegmentCache`、`KeepaliveTimer`。
3. 业务事实通过 5 个最小钩子外发；位置/报警是当前唯一有明确钩子覆盖的业务类别。
4. 平台下行消息一律不属于 gateway 入站；需要下发时由北向系统负责。

### 5.2 代码无法定论、需产品/架构决策的待定项

| 编号 | 待定项 | 事实依据 | 影响 |
|---|---|---|---|
| C1 | 平台 0x8203 人工确认报警的关联是否保留 | 0x0001 的 `AnswerMessageID == 0x8203` 会调用 `AlarmCache.ConfirmByCommand`；gateway 不接收平台下行，因此该路径当前不可达 | 若未来 gateway 转发 0x8203，需要保留 `AlarmCache.commands`（只留关联，不留事件） |
| C2 | 0x0003 注销是否触发 `OnDisconnect` | 当前钩子只在会话关闭时触发；注销后终端可能仍保持连接 | 影响下游对"离线"的理解；需明确"注销"与"断开"是否等价 |
| C3 | 业务查询应答（0x0104/0x0107/0x0201/0x0608/0x0802/0x1205）如何回到北向系统 | gateway 不实现北向 API，broker 无 waiter；现有钩子也没有应答类事件 | 决定 M3 是否需要"请求-应答"型钩子或北向接口 |
| C4 | 未被钩子覆盖的业务上行是否补通用钩子 | 0x0108、0x0301–0x0303、0x0500、0x0700–0x0705、0x0800–0x0805、0x0900/0x0901、0x1205 目前只应答 | 若下游需要这些数据，最小 5 钩子不够，需扩展 `Hooks` |
| C5 | 0x0704 批量定位的通知粒度 | 现有实现逐条触发 `OnLocation`/`OnAlarm` | 逐条 vs 聚合会影响下游流量与幂等设计 |
| C6 | 0x0801 媒体数据是否走钩子 | 媒体体可能很大，现有钩子不携带媒体载荷 | 需要决定是异步引用、对象存储还是完全交给其他通道 |
| C7 | `alarmSign != 0` 是否等价于"报警事件" | 报警标志位含多种状态/事件位，协议未区分"需通知"的子集 | 可能产生大量非紧急通知；需业务侧确认过滤规则 |
| C8 | 0x0200 的 ACC 休眠状态写入 device 是否算连接现场 | 现有实现在 ACC 关闭时把设备状态置为 Sleeping | 本规格按"连接现场"保留；若产品认为属于业务状态，需移出 |
| C9 | 分包缓存的 TTL/容量对 gateway 是否足够 | 当前 TTL 2 分钟、16 MiB、1024 条 | 高并发或大帧场景可能需要按部署形态调参 |

以上待定项不影响"删除实验性模式开关"这一步；实现 gateway 时需先关闭对应决策。
